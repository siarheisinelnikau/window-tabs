# Architecture

## Ownership and flow

`model.rs` implements groups over a `WindowAdapter` interface. It captures every original before the first side effect, checkpoints the combined recovery journal, and only then presents/hides members. Detach/close restore before dropping records. A close request or failed detachment enters a restoration-only phase: failed records stay in the group and journal, with presentation/hiding and automatic synchronization disabled. Exit pruning is committed only after its journal write succeeds and reveals a new member only in the group that lost its active window. Inactive-member exit/detachment cannot restore a minimized group. Shutdown retries a failed final journal write even after all groups have been removed. One-member groups remain useful after a member exits; the final exit removes the group.

`platform.rs` is the Win32 adapter. `EnumWindows` filters ordinary, visible, enabled, captioned, resizable, non-owned, non-topmost windows. Process query access, elevation, DWM cloaking, responsiveness, PID, creation time, and class are checked. It snapshots `WINDOWPLACEMENT` in workspace coordinates and also saves the normal rectangle in physical screen coordinates; older journals omit the latter field and use a compatibility conversion. Original minimized and maximized states are recovered with `SetWindowPlacement`; workspace coordinates are not passed directly to `SetWindowPos`. For a removed monitor the adapter chooses a reachable normal rectangle, converts it into the selected monitor's workspace, and requires that exact requested placement before clearing the record. It does not treat visibility alone as proof of restoration.

The UI thread owns all manager/strip controls and process-scoped `SetWinEventHook` subscriptions with `WINEVENT_OUTOFCONTEXT`. It runs a blocking `GetMessageW` loop. WinEvent callbacks only post a coalesced notification; a one-shot 75 ms timer bounds bursts. No timer runs while idle and there are no keyboard hooks. The strip is adjacent to the active member in Z-order and is not globally topmost. Target parent/owner/style and application content are not changed.

`controller.rs` owns state on one worker with a 32-command bounded channel. Window enumeration, identity queries, grouping, restoration, settings serialization, and journal writes happen there. Small snapshots wake the native UI through `PostMessageW`; UI reads do not wait for disk/network operations. Window changes use asynchronous native requests and bounded 300 ms acknowledgments on the worker. A timeout is reported and retains restoration records. A 150 ms responsiveness probe is used before capturing a selected window. The UI does not claim a queued OS request is a completed restoration.

`storage.rs` writes versioned JSON to a same-directory temporary file, flushes it, and replaces the destination with `MoveFileExW`. Corrupt/future-schema files are preserved. A valid journal can still be recovered when settings fail to load; settings writes and new grouping are disabled and no startup update request is made in that mode. The singleton mutex prevents multiple normal instances from racing over data. Recovery from a previous session is an explicit user action, never an automatic desktop change on startup.

`update.rs` uses public HTTPS through Windows WinHTTP, stable semver comparison, canonical asset paths, a size cap, SHA-256, and an x64 GUI PE32+ check with section/entry-point validation. Each attempt atomically reserves a new download directory, copies and verifies the current executable as its helper, and records both old/new hashes. The UI permits at most one download worker. Installation replies carry request IDs and persist across coalesced snapshots, so an intervening event cannot erase a refusal or associate an old reply with a retry. An install-specific shutdown command requires completed previous-session recovery and successful current-group restoration. An ordinary close cannot authorize installation.

`install.rs` separates the replacement transaction from native filesystem/process operations. After parent exit it checks the old hash again, exclusively creates unique staging and backup files on the destination volume, verifies both, and rechecks the target before atomic replacement. Existing sidecars are preserved; only files created by the transaction are cleaned. Failure to start the new image copies the verified backup back into place and attempts to restart the old image, preserving the backup even if rollback/restart fails. Tests use an in-memory filesystem and fake launcher. Native helper execution, process waiting, replacement, and restart are not exercised. A process that starts and then crashes is not detected automatically; the backup supports manual recovery.

The manifest requests `asInvoker` and `PerMonitorV2`. The x64 MSVC configuration links the CRT statically for a single executable. Native standard controls/GDI provide the UI; the application has no graphics render loop, GPU renderer, telemetry, plugin injection, WebView, driver, or service. Idle CPU and perceptual responsiveness have not been measured.

## API references consulted

- [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos): asynchronous placement, visibility, and Z-order flags.
- [WINDOWPLACEMENT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-windowplacement): saved show state, asynchronous restoration, and workspace-coordinate semantics.
- [GetWindowPlacement](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowplacement): normalized show state; its documented flags output does not guarantee the original restore-to-maximized preference of an already-minimized window. That edge case requires manual validation.
- [SetWindowPlacement](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowplacement): restoration and OS adjustment of offscreen placements.
- [ShowWindowAsync](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindowasync): request acceptance is distinct from target completion.
- [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook): process filtering, out-of-context callbacks, and message-loop requirements.
- [WinHttpSetOption](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpsetoption): request redirect policy.
- [PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format): COFF characteristics, PE32+ optional headers, sections, and entry-point backing.
